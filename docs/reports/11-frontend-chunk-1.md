## What was done

Re-dispatched frontend chunk 1 (season overview + race detail pages) to Gemini after diagnosing and fixing the quota blocker from stage 10.

## The Gemini quota fix

- Confirmed via a direct 429 error that the CLI's default model is `gemini-3.5-flash`, with an extremely low free-tier quota (`limit: 5`–`20` requests/day) — unusable for an agentic coding task.
- Tried the interactive Google OAuth login path (motivated by the user having a Google Pro subscription) as a way around it. Dead end: `IneligibleTierError`, Google explicitly redirects individual-account OAuth login on this CLI to a separate product ("Antigravity"), regardless of subscription tier.
- Found `gemini-flash-lite-latest` has a separate, much less restrictive quota pool and works immediately. Pinned all future dispatches to it via `-m gemini-flash-lite-latest` in `docs/orchestration.md`.

## Bug found in review (mine, not Gemini's)

`frontend/lib/api.ts`'s `Circuit` interface was missing the `technical_characteristic` field entirely — a gap dating back to the original frontend scaffolding (stage 05), which predates the contract's stage-06 addition of that field. I never went back and updated the typed client when the field was added.

Gemini's code compiled fine because TypeScript doesn't know the *runtime* shape, only the *declared* one — so it worked around the missing type by inventing a locally-scoped `ExtendedCircuit` interface with a field named `technical_characteristics` (**plural** — wrong). This would have silently always shown "N/A" for downforce level and key trait at runtime, since the real API field is `technical_characteristic` (singular), and `tsc`/`npm run build` have no way to catch a naming mismatch against data they never see.

Fixed by adding the missing field to the shared `Circuit` type in `lib/api.ts` (matching `docs/api-contract.md` exactly) and updating the race detail page to use it directly, removing the workaround. Re-ran `tsc --noEmit` clean.
